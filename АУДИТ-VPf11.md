# Аудит кода: что было не так и как исправлено

Исходный файл: `legacy/utils_bad.py` (сохранён только для сравнения).
Исправленный код: `app/db.py`, `app/users.py`, `app/api.py`.
Проверки: `tests/test_users.py`, `tests/test_api.py`.

## Как проводился аудит

1. Прочитан исходный модуль целиком, выписаны все обращения к БД, файлам и общему состоянию.
2. Для каждой функции проверено: что обещает докстринг, что возвращает на самом деле,
   что будет при пустом, битом и враждебном вводе.
3. Отдельно проверены места, где данные попадают в SQL-строку, в файл и в общий список.
4. Каждый пункт закрыт либо исправлением с тестом, либо осознанным решением (см. в конце).

## Что осталось осознанным решением

- **Пароли в БД, а не в файле.** Файл `passwords.txt` не даёт ни уникальности, ни транзакций;
  отдельная таблица `passwords` проще и честнее.
- **`check_same_thread`.** Соединение открывается на каждый запрос и закрывается в том же потоке,
  поэтому флаг не нужен и не отключается.
- **Dev-сервер не используется.** `run.py` поднимает `waitress` — работает и на Windows, и в контейнере,
  и не является «только для разработки».
- **Аутентификация в API не добавлена.** По ТЗ она вне объёма: сервис учебный, эндпоинты
  без авторизации; в README это отмечено как ограничение.
