# ТЗ: аудит кода и Docker-сервис users API

Учебный проект по уроку **VPf11 «Кейс 3: AI для кода»**.
Версия 1.0. Сдача — репозиторий: аудит, исправленный код, README, OpenAPI, Dockerfile, скриншоты запуска.

## 1. Цель

Пройти полный цикл работы с кодом через ИИ:

1. взять намеренно плохой модуль с типичными ошибками и уязвимостями;
2. провести аудит: проблема → риск → исправление;
3. переписать модуль и обернуть его в рабочий HTTP-сервис;
4. задокументировать (README, OpenAPI) и упаковать в Docker;
5. собрать образ, запустить контейнер и проверить реальными запросами.

Акцент — не «сгенерировать код», а **доказать, что стало безопаснее и работает**: тесты на инъекции,
хеширование, гонки потоков и контракты API.

## 2. Что аудируем

Файл `legacy/utils_bad.py` — воспроизведение антипаттернов из урока:

| № | Проблема в коде | Риск |
|---|---|---|
| 1 | SQL через f-строку и `%` | SQL-инъекция: `' OR 1=1 --` |
| 2 | `tags=[]` — мутируемый аргумент | список «протекает» между вызовами |
| 3 | `return cur.lastrowid + ""` | тип не соответствует обещанному `int` |
| 4 | соединение SQLite не закрывается | утечка файловых дескрипторов, блокировки |
| 5 | «хеш» `password[::-1]` | пароли восстановимы обратным чтением |
| 6 | `open()` без `with` | файл не закрывается при ошибке |
| 7 | `active_users` без блокировки | гонка потоков, потеря данных |
| 8 | `time.sleep(0.1)` и удаление первого элемента | искусственная задержка, странная логика |
| 9 | `return {}` вместо `None` | контракт нарушен, `if not user` врёт |
| 10 | `json.loads` без обработки | исключение на битых данных |
| 11 | `except: return True` в `is_admin` | любой сбой → админ |
| 12 | `self_test` с ложными проверками | «зелёный» тест при поломке |
| 13 | нет валидации входа | пустые имена, не-строки в тегах |
| 14 | нет health-check | сервис нечем проверить |
| 15 | traceback уходит клиенту | раскрытие внутренностей |

Результат аудита оформляется файлом `АУДИТ-VPf11.md` с таблицей и выводом по каждой строке.

## 4. Исправления, которые доказываются тестами

| Что | Как исправлено | Чем доказано |
|---|---|---|
| SQL-инъекция | параметризованные запросы `?` | тест: имя `' OR 1=1 --` создаёт запись дословно, база цела |
| Мутируемый аргумент | `tags=None` → локальная копия | тест: два вызова не делят список |
| Тип возврата | `int(cur.lastrowid)` | тест: `isinstance(...) is int` |
| Соединения | `@contextmanager` + `finally: close` | тест: файл БД не заблокирован после 200 вставок |
| Пароли | `hashlib.pbkdf2_hmac("sha256", ..., 100_000)`, соль 16 байт, формат `salt$hash` | тесты: хеш ≠ пароль, одинаковые пароли дают разные хеши, `verify_password` работает |
| Файлы | `with open(..., encoding="utf-8")` | — |
| Гонка потоков | `threading.Lock`, снапшот `get_active_users_snapshot()` | тест: 200 потоков, длина не превышает лимит |
| Контракты | `None` вместо `{}`, `json.loads` в try | тест: пользователя нет → `None` |
| `is_admin` | строгая проверка `isinstance(dict)` и `role == "admin"` | тест: `None`, строка, `{"role": "Admin"}` → False |
| Валидация | имя 1–80 символов, до 10 тегов, каждый до 40 | тесты API: 400 на мусор |
| Ошибки | обработчики возвращают JSON без traceback | тест: 404 и 500 в JSON |
| Health-check | `GET /health` проверяет БД | тест + `HEALTHCHECK` в Dockerfile |

## 5. API

| Метод | Путь | Тело / параметры | Ответ |
|---|---|---|---|
| POST | `/adduser` | `{"name": "Иван", "tags": ["стартер"], "password": "..."}` | 201 `{"id": 1, "name": "...", "tags": [...]}` |
| GET | `/user/<id>` | — | 200 объект пользователя, 404 если нет |
| GET | `/user?name=Иван` | query | 200 или 404 |
| POST | `/activate/<id>` | — | 202 `{"active": [...], "count": n}` |
| GET | `/active` | — | 200 `{"active": [...], "count": n}` |
| GET | `/slow?n=1000` | query, 1 ≤ n ≤ 100000 | 200 `{"n": ..., "result": ..., "seconds": ...}` |
| GET | `/health` | — | 200 `{"status": "ok", "db": "ok"}` |

Все ошибки — JSON `{"error": "..."}` с кодом 400/404/405/500. Пароль не возвращается никогда.

## 6. Docker

- Базовый образ `python:3.12-slim`, рабочая папка `/app`.
- `pip install --no-cache-dir -r requirements.txt` отдельным слоем (кэш зависимостей).
- Непривилегированный пользователь `appuser`.
- `EXPOSE 8000`, `HEALTHCHECK` на `/health`, запуск через `waitress` (4 потока).
- Наружу — `8090`: `docker run -d --name vpf11-api -p 8090:8000 vpf11-api:1.0`.
- `.dockerignore`: `.venv`, `__pycache__`, `tests`, `*.db`, логи, `.git`.

Порт 8080 не используем: он занят другим контейнером на этой машине.

## 7. Проверки

- `pytest` — юнит-тесты и тесты API через `test_client` (без запуска сервера).
- `python test_endpoints.py --url http://127.0.0.1:8090` — живая проверка всех маршрутов, печатает код и краткий ответ, при ошибке завершается с кодом 1.

## 9. Критерии приёмки

| № | Критерий | Как проверить | Признак |
|---|---|---|---|
| 1 | Тесты проходят | `pytest -q` | все `passed` |
| 2 | Аудит оформлен | открыть `АУДИТ-VPf11.md` | таблица с 15 пунктами и выводом |
| 3 | Сервис запускается локально | `python run.py` | лог «слушаю 0.0.0.0:8000» |
| 4 | Инъекция не проходит | `pytest -k injection` | имя сохраняется как текст |
| 5 | Хеши корректны | `pytest -k password` | хеш ≠ пароль, соль разная |
| 6 | Гонки нет | `pytest -k threads` | длина активных ≤ лимита |
| 7 | Контракты | `pytest -k api` | 201/200/202/400/404 в JSON |
| 8 | Образ собирается | `docker build -t vpf11-api:1.0 .` | `Successfully tagged` |
| 9 | Контейнер работает | `docker ps` | `Up`, состояние `healthy` |
| 10 | Все эндпоинты живы | `python test_endpoints.py --url http://127.0.0.1:8090` | 7 из 7 `ok` |
| 11 | README и зависимости | открыть `README.md`, `requirements.txt` | есть команды запуска |
| 12 | OpenAPI | открыть `openapi.yaml` | 7 путей, схемы, коды |
| 13 | Секретов в образе нет | `docker history`, `grep` по коду | нет токенов и паролей |
| 14 | Данные не в git | `git status` | `users.db`, `.env`, логи не в индексе |

## 10. Что не входит

- деплой на сервер и Docker Hub (по решению — пропускаем);
- аутентификация и роли на уровне API;
- ORM, миграции, PostgreSQL;
- HTTPS и reverse-proxy;
- нагрузочное тестирование.

## 11. Бюджет сложности

Один сервис, одна таблица, семь эндпоинтов, два десятка тестов. Новое допускается, только если
усиливает проверяемость: тест на инъекцию, тест на гонку, хеш с солью, health-check, скрипт
проверки эндпоинтов.
